# 2026-08-30 — 从一张照片到上线的工具

第一次会话。起点是一张拍歪的装订户口本照片，终点是 https://flatpage.pages.dev
上线可用。

## 怎么走到这一步的

先写 Python 版把算法跑通（`tools/dewarp.py`），确认效果之后才移植到浏览器。
这个顺序是有意的：算法参数要试错，命令行迭代比浏览器快得多。Python 版留在仓库
里当参考实现，浏览器版以它的输出为基准校验。

## 关键的技术判断

**用表格框线做校正基准，而不是文本行。** 通用展平模型（page_dewarp、DewarpNet、
UVDoc、DocTr++）靠拟合文本行走向反推页面形状 —— 那是一个推断。而表格框线**本来
就该是直的**，在它们身上测到的偏差就是形变本身。对表格、证件、横格纸，这比学习
模型更准，还不用往浏览器塞几百 MB 权重。纯段落文字没有格线，那种情况退回纯透视
校正，学习模型仍然更强。

**纯前端，不是为了省服务器成本。** 用户拿来处理的是户口本、护照、身份证。任何
「上传到我们服务器」的方案在这个品类里先天残疾。全本地处理让最大的顾虑变成最强
的卖点，而且是可验证的 —— 断网还能用。

**预览和导出是两条精度路径。** 预览跑 1000px 缩略图（约 200ms），导出跑全分辨率
（约 2.4s）。拖角点时每帧跑全分辨率要 2.4 秒，交互直接废掉。**验证时两条都要测，
测一条不能说明另一条。**

## 踩过的坑

**四点透视变换消不掉书脊弯曲。** 那不是一个平面。四点变换做完，表格线仍有 28px
起伏，必须再用格线做一次位移场 remap。

**横线检测一开始返回 0 条。** 表格线只跨图宽的 93%（两侧有页边），而采样格子铺满
整个图宽，最外侧永远采不到像素，于是 11 条线被全票否决。改成按各线的公共 x 跨度
取样。

**HEIC 不应用 EXIF 旋转。** `cv2.imread` / `createImageBitmap` 会自动转，PIL 不会。
同一张照片存成 JPG 正常、存成 HEIC 就躺倒。

**双语 SEO 是空的，而且英文版也是。** 文案全靠 JS 运行时注入，爬虫拿到的 HTML 里
`<h1>` 是空标签。不只中文版不存在 —— 英文版同样没有可索引内容。改成构建时预渲染
两套静态 HTML 后，服务端返回的中文字符从 2 个变成 537 个。

**UMD 只在 dev 炸。** 详见 [docs/BUILD.md](../docs/BUILD.md)。生产构建有 rollup
的 commonjs 插件遮住了它，dev 白屏。**「生产能跑」不等于「dev 能跑」，反之亦然。**

**本地能跑 ≠ CI 能跑。** CI 里内联的 `grep -oE '[一-龥]'` 在 macOS 的 BSD grep 下
正常，在 runner 的 GNU grep + C locale 下报 `Invalid collation character` 并返回
0 匹配，于是一个完全正确的构建被判失败。根因不是 locale，是**本地检查和 CI 检查
是两份代码**。抽成 `tools/verify-dist.py` 一份，两边都调它。

**我自己的校验脚本有 off-by-one。** 验 PDF 的 xref 表时，把 free entry 那行算成了
obj 1，报了 8 处「偏移错位」。PDF 本身是对的。教训：验证代码出错时，先怀疑验证
代码。

## 体积

opencv.js 从 12.7MB 降到 1.85MB（传输 3.65MB → 490KB），做法是只白名单实际调用的
17 个函数。jsPDF 换成 1.3KB 自写 PDF 生成器（它为用不到的功能拖进 html2canvas +
dompurify 共 780KB）。worker 改成首次使用才创建，首屏 11KB。

## 部署

**正式入口 `flat.bybrowser.com`**（Cloudflare Pages）。`bybrowser.com` 作主站，
以后每个工具挂一个子域 —— 注意 Google 把子域当独立站点评估，主域权重传过来很有限，
每个工具基本各自养权重。

`chaxus.github.io/flatpage/` 是开源演示页，由 `.github/workflows/deploy.yml` 在
推 main 时自动部署，构建时带 `FLATPAGE_NOINDEX=1`（robots meta 改 noindex +
robots.txt 全 Disallow），避免和正式站抢权重。

部署地址由 `FLATPAGE_BASE` / `FLATPAGE_ORIGIN` / `FLATPAGE_NOINDEX` 三个环境变量
驱动，改域名只需改 `vite.config.js` 里的默认值。

## 上线后的优化（同日）

**兑现离线承诺。** 首页一直写着「关掉 Wi-Fi 它照样能用」，但根本没有 Service
Worker —— 刷新就白屏。**页面上的承诺没有实现，这比缺功能更糟。** 现在 SW 分两层
缓存：shell（约 30KB）在 install 时 precache，wasm（1.8MB）等第一次真正用到才
缓存，所以首访代价不变、用过一次之后完全离线可用。文案也改准确了（「首次访问后」）。

**修掉 soft 404。** CF Pages 默认把未匹配路径 fallback 成 index.html + 200，于是
任意 URL 都是「有效页面」，搜索引擎会收录无限多的假页面。放了 404.html 之后返回
真 404。

**CDP 的离线模拟对经过 Service Worker 的请求不生效。** 这个坑很深：模拟离线后
页面能打开、图片能处理，看起来「离线成功」，但同源 fetch 仍能拿到 HTTP 404 ——
说明网络根本没断，那次「验证」什么都没证明。**必须做对照实验**：注销 SW + 清空
缓存后再离线导航，得到 `ERR_INTERNET_DISCONNECTED`，才证明离线模拟对导航有效、
因而之前的成功确实是 SW 的功劳。

**toast 只显示 3.6 秒，自动化里抓不到。** 反复用 MutationObserver 和高频轮询都
落空，无法区分「没触发」和「在观察开始前就消失了」。给 toast 加一行
`console.debug` 之后才能确证（`[flatpage] toast: Cached...`）。**瞬时 UI 要留
可观测痕迹，否则没法验证。**

**触摸目标比设计值小 2.5 倍，而桌面端把这个 bug 藏住了。** 角点把手的半径按
「显示尺寸多少 px」反算，取宽度用的是
`srcCanvas.getBoundingClientRect().width || srcCanvas.width`。布局没完成时前者是
0，于是 fallback 到 canvas 的**位图**宽度 900，而窄屏的**显示**宽度只有 360 ——
把手被算小 2.5 倍（视觉 7px、命中区 18px，远低于 Apple 的 44px 指南）。桌面端两个
值接近，所以一直没暴露。**修的过程中我先换了 `getScreenCTM().a`，结果更糟**（它
在这里返回单位矩阵，把手只剩 1px）。最终方案是取覆盖层的真实显示宽度，拿不到就
`requestAnimationFrame` 等下一帧。教训：**"有 fallback" 不等于安全，fallback 到
一个量纲不同的值比直接失败更难发现。**

**CF Pages 部署有短暂的传播窗口。** 部署刚完成时访问，可能 HTML 已更新而 assets
还没跟上，入口 JS 404、整站打不开。几秒后自愈。部署后立即验证要把这一点考虑进去。

## 反馈驱动的第二轮（同日）

**「框住了整张图」是真 bug，而且是我换 OpenCV 版本引入的回归。** 一张户主页照片
（表格仅 4 行且被两枚大印章覆盖）在自建的 4.x 下一个四边形都找不到，静默退回
default frame（整图 6%~94%），看起来就是「整张图」；而「重置角点」恢复的正是这个
失败结果，所以按了没反应、像坏的。同一张图在上游 5.0 下检测正常 —— 我此前把版本
差异描述为「角点差几像素，在预期内」，那只对简单样张成立。

修法是三层：多组阈值参数轮流试 → 找不到四边形就用最大轮廓的最小外接矩形 →
仍失败才返回 null。另外给检测加了面积上限（>85% 的候选直接排除，>82% 覆盖率视为
失败），因为文档不会占满整个画面，占满就说明框到了整图或跨页外轮廓。

**修一张图时把另一张弄坏了。** 为难例把 approxPolyDP 容差放宽到 0.08，第二张成功
了，第一张却被框成完全不同的区域（比例从 1.32 变成 0.68）——**只测第二张的话，
看起来就是「修好了」**。回退到 0.05 后两张都对。基线记在
`private-samples/BASELINE.md`，改检测参数必须两张都跑。

**「应用到全部」写了没人读的字段。** 我加的按钮把设置写进 `d.opts`，而预览和导出
读的仍是全局 UI 开关，按下去完全没效果。改成每页各自持有设置、UI 只是当前页的
视图之后才真正生效（已验证：A 页关掉拉直、切到 B 页、再切回 A，两页各自保持）。

其余：剪贴板粘贴、批量下载 JPG 带进度、拖角点放大镜、移动端 38–40px 控件与
sticky 操作栏。

## 自由画布（同日）

固定版式之外加了「自由排布」：先按页数自动铺到 A4 上，再拖动 / 等比缩放微调。
画布上摆的是预览分辨率的图（快），导出时按同一套**比例坐标**重绘全分辨率 ——
实测导出 A4 上两个内容块的 x/y/w/h 百分比与画布逐位一致。

三个坑：

**模块顶层的初始化撞上 TDZ。** `applyLang()` 在模块顶部就执行，它调用的
`updateModeUI` 内部用到画布那一段的 `const isFree` / `const sheet` —— 那时还在
暂时性死区。压缩后不是 ReferenceError 而是 `TypeError: q is not a function`，
更难认。改成：applyLang 只管文案，所有依赖后置定义的刷新收进 `refreshChrome()`，
在文件末尾调一次。

**pointerdown 里重建 DOM，把正在拖的节点换掉了。** 选中时调用 `renderSheet()`
重建全部元素，拖动看起来「没反应」。改成只切 class。

**非当前页在画布里是空框。** 预览只为「当前选中页」生成，其余页没有 `preview`。
切到自由排布时要把缺的补齐。

另外拖动原本允许元素一半出纸 —— 打印时出界就是丢内容，改成夹在纸内（图比纸大时
反向夹，否则会卡死在角上）。
